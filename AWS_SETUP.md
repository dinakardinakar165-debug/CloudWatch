## 1. Overview of Mode A

Mode A enables customer-approved, read-only telemetry querying across accounts without exchanging persistent credentials (`AWS_ACCESS_KEY_ID` or `AWS_SECRET_ACCESS_KEY`).

### Core Security Guarantees
1. **No Root or Admin Access**: Never requires administrator privileges or root credentials.
2. **Confused Deputy Mitigation**: Mandates a unique `sts:ExternalId` generated by CloudWatch Sentinel.
3. **Ephemeral STS Sessions**: Obtains short-lived (1-hour) security tokens via AWS STS `AssumeRole`.
4. **Immediate Revocation**: Deleting or modifying the IAM role in your AWS console instantly terminates Sentinel's access.

## 2. Step-by-Step Setup Instructions

### Step 1: Obtain Your Unique External ID
1. Log into your CloudWatch Sentinel console.
2. Navigate to **AWS Connections** (`/aws_connections`).
3. Under **Cross-Account Configuration**, copy your assigned **Sentinel Account ID** (`38578049108`) and unique **External ID** (e.g. `sentinel-ext-live-729410`).

---

### Step 2: Create the IAM Role via AWS CLI or Console

#### Option A: Using AWS CLI

1. Create a trust policy file `trust-policy.json`:
```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowCloudWatchSentinelAssumeRoleWithExternalID",
      "Effect": "Allow",
      "Principal": {
        "AWS": "arn:aws:iam::38578049108:root"
      },
      "Action": "sts:AssumeRole",
      "Condition": {
        "StringEquals": {
          "sts:ExternalId": "YOUR_EXTERNAL_ID_HERE"
        }
      }
    }
  ]
}
```

2. Create the IAM Role:
```bash
aws iam create-role \
  --role-name CloudWatchSentinelReadOnlyRole \
  --assume-role-policy-document file://trust-policy.json \
  --description "Read-only telemetry role for CloudWatch Sentinel with ExternalId guard"
```

3. Create the least-privilege permissions policy file `sentinel-permissions.json`:
```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "CloudWatchTelemetryReadOnly",
      "Effect": "Allow",
      "Action": [
        "cloudwatch:GetMetricData",
        "cloudwatch:ListMetrics",
        "cloudwatch:DescribeAlarms"
      ],
      "Resource": "*"
    },
    {
      "Sid": "EC2MetadataReadOnly",
      "Effect": "Allow",
      "Action": [
        "ec2:DescribeInstances",
        "ec2:DescribeInstanceStatus"
      ],
      "Resource": "*"
    },
    {
      "Sid": "CostExplorerAggregatesReadOnly",
      "Effect": "Allow",
      "Action": [
        "ce:GetCostAndUsage"
      ],
      "Resource": "*"
    },
    {
      "Sid": "CodePipelineExecutionReadOnly",
      "Effect": "Allow",
      "Action": [
        "codepipeline:ListPipelines",
        "codepipeline:GetPipelineState",
        "codepipeline:ListPipelineExecutions",
        "codebuild:ListBuilds",
        "codebuild:BatchGetBuilds"
      ],
      "Resource": "*"
    }
  ]
}
```

4. Attach the permissions policy to the role:
```bash
aws iam put-role-policy \
  --role-name CloudWatchSentinelReadOnlyRole \
  --policy-name SentinelLeastPrivilegePolicy \
  --policy-document file://sentinel-permissions.json
```

---

### Step 3: Validate the Role in Sentinel
1. In CloudWatch Sentinel, paste the Role ARN:
   ```
   arn:aws:iam::ACCOUNT_ID:role/CloudWatchSentinelReadOnlyRole
   ```
2. Select your primary AWS Region (e.g. `us-east-1` or `ap-south-1`).
3. Click **Validate & Connect**.
4. The system validates each permission scope (`cloudwatch:GetMetricData`, `ce:GetCostAndUsage`, etc.) without failing the entire platform if one optional scope is unconfigured.

---

## 3. Revocation Procedure

To instantly revoke CloudWatch Sentinel's access:
```bash
# Delete the role policy
aws iam delete-role-policy \
  --role-name CloudWatchSentinelReadOnlyRole \
  --policy-name SentinelLeastPrivilegePolicy

# Delete the role entirely
aws iam delete-role \
  --role-name CloudWatchSentinelReadOnlyRole
```
Once deleted, all subsequent STS `AssumeRole` calls fail immediately with `AccessDenied`, preventing further data collection.
